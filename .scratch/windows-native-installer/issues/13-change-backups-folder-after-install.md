# 13：安裝後變更備份資料夾

**規格：** `.scratch/windows-native-installer/spec.md`

**要做什麼：** 備份資料夾目前只能在安裝時決定，升級時 `/BACKUPSDIR` 也會被忽略，Web UI 的本機儲存也沒有路徑欄位。C: 空間不夠時，系統管理者沒辦法把之後的備份改放到另一顆硬碟。這張單讓系統管理者在安裝後，從 Web UI 的「Databasus 設定」或重新執行安裝程式變更備份資料夾，而且已經存在的備份都還能還原。

**Blocked by：** none

**狀態：** ready-for-agent

**設計：**

- 唯一的設定來源是程式資料目錄下的 `backups-folder.txt`，記錄目前的備份資料夾（`current=`）和以前用過的資料夾（`previous=`）。檔案用嚴格的 ACL 保存，launcher 和後端只接受由 SYSTEM、Administrators 或服務本身帳戶擁有的檔案，避免一般使用者先放一個檔案，把 LocalSystem 的寫入導向別處。
- launcher 啟動時讀這個檔案，把目前的資料夾交給後端。只有檔案還不存在時，才用 `-backups-dir`（或預設的 `<程式資料目錄>\backups`）建立它；之後檔案優先，服務的命令列不再帶 `-backups-dir`，所以不會蓋掉 Web UI 的設定。安裝程式透過 `databasus-launcher.exe backups-folder -set` 寫入，Web UI 由後端寫入，兩邊讀寫同一個檔案。
- 既有備份不搬移。變更後，舊的資料夾移到 `previous`，新的備份寫到新資料夾；本機儲存讀取和刪除檔案時，先找目前的資料夾，再依序找以前的資料夾。所以舊備份照樣能還原，保留政策照樣會刪除它們，空間會隨著舊備份到期慢慢釋出。要立刻釋出空間的話，可以停止服務，把檔案手動移到新資料夾。選這個做法是因為搬移需要複製、驗證、可續傳、避開執行中的備份，比較複雜，而且搬移途中失敗會讓備份處於兩邊都不完整的狀態。
- 變更立即生效，不需要重新啟動服務。執行中的備份會在結束時放到當時的目前資料夾，兩邊都找得到。
- 驗證在後端（以 LocalSystem 執行）進行，和安裝程式的 `check-install` 共用同一段程式：必須是本機固定磁碟上的絕對路徑（不接受 UNC、網路磁碟、卸除式磁碟），不能是磁碟根目錄、Windows 目錄、Program Files、ProgramData 或使用者資料夾本身，也不能在程式資料目錄或安裝目錄裡（預設的 `<程式資料目錄>\backups` 除外）。資料夾不存在時會建立，並實際寫入再刪除一個測試檔，確認服務帳戶能寫入。
- Linux 和 Docker 的行為不變：沒有 launcher 提供設定檔時，這個設定不顯示，API 回答不能變更。

- [ ] 「Databasus 設定」頁面只對執行個體管理員顯示目前的備份資料夾和以前用過的資料夾，並可以變更；非管理員呼叫 API 會得到 403。
- [ ] 不合規定的路徑（相對路徑、UNC、不存在的磁碟、系統資料夾、磁碟根目錄、服務帳戶無法寫入）會被拒絕，並說明原因；合規的資料夾不存在時會自動建立。
- [ ] 變更會寫入稽核紀錄（舊資料夾 → 新資料夾）。
- [ ] 變更後的新備份寫到新資料夾，變更前的備份還能還原和刪除。
- [ ] 設定在服務重新啟動和安裝程式升級後都保留，服務命令列的 `-backups-dir` 不會蓋掉它。
- [ ] 升級時 `/BACKUPSDIR` 和精靈的資料夾頁面可以變更備份資料夾（程式資料目錄仍不能變更），用同一套驗證；沒指定時沿用目前的資料夾，包括 Web UI 改過的。
- [ ] 完整解除安裝並選擇刪除所有資料時，目前和以前的備份資料夾裡 Databasus 的檔案都會刪除。
- [ ] Linux 和 Docker 的行為不變。
- [ ] `packaging/windows/README.md` 說明變更方式和規則。
